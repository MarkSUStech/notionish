# Notionish AI 辅助模式 — 设计文档

## 目的

在 Notionish 右侧加入可折叠的全功能 AI 助手面板：基于整个工作区的笔记知识库做检索增强问答，并可按指令读写笔记。笔记数据始终以浏览器 `localStorage` 为唯一数据源。

## 理解摘要

- 右侧可折叠的全功能 AI 助手面板。
- AI 来源为 RAG：本地 embedding（Ollama，可远程部署）+ OpenAI 兼容接口的主 LLM。
- 权限为可读可写；写操作必须经用户确认后才写入。
- 检索范围为整个工作区（页面、块、题目、闪卡）。
- 功能六项：知识库问答、总结页面/选中块、写作辅助、生成题目/闪卡、学习辅导、直接编辑笔记。

## 决策记录

| 决策 | 选择 | 备选 | 理由 |
| --- | --- | --- | --- |
| 面板形态 | 右侧侧边面板 | 悬浮窗 / 底部面板 / 全屏页 | 不遮挡笔记、可折叠，贴合 Notion AI 习惯 |
| 模型来源 | Ollama embedding + OpenAI 兼容 LLM | 纯本地 / 纯云端 | 知识库检索本地化，生成能力强 |
| 写入权限 | 可读可写，写需确认 | 只读 / 完全自主 | 兼顾效率与安全 |
| 检索范围 | 整个工作区 | 当前页 / 混合 | 跨页问答，知识库最全 |
| 实现方案 | B：服务端全托管 RAG | A：服务端代理 + 浏览器内检索 / C：浏览器直连 | 检索更快，向量库可扩展 |
| 索引同步 | 增量同步 + 全量重建 | 全量快照 / 服务端拉取 | 快且省，保留重建入口 |
| 数据归属 | 浏览器 localStorage 为唯一数据源 | 服务端镜像为准 | 保持现有离线定位，服务端索引仅派生缓存 |

## 最终设计

### 组件

**服务端（`node server.js` + 新模块 `server-ai.js`）**
- 分块：工作区内容切成约 500 字片段，附 `pageId`/`blockId`/标题。
- 向量库：内存索引 + 持久化到 `data/ai-index.json`。
- 检索：embedding → 余弦 top-k → 带引用片段。
- 配置：`ai-config.json`（ollamaUrl、embedModel、openaiBaseUrl、openaiApiKey、openaiModel），Key 不发给浏览器。

**浏览器（新 `js/ai.js`）**
- 右侧抽屉：消息流、流式渲染、来源引用、设置、写入确认。
- 索引同步：监听 Store 变更，防抖增量推送 + 「重建全部索引」。
- 数据源仍为 `localStorage`，写操作走 Store。

### 端点

- `POST /api/ai/embed`：转发 Ollama 取向量。
- `POST /api/ai/query`：端到端「embed → 检索 → 组 prompt → 调 LLM」，SSE 流式返回 `{delta, citations}`。
- `POST /api/ai/index/upsert`：增量建索引。
- `POST /api/ai/index/delete`：删除某页面/块的片段。
- `POST /api/ai/index/rebuild`：全量重建。

### 写入确认

AI 提议写操作 → 面板展示结构化草稿（目标、操作、diff/预览）→ 用户点「应用」才执行 → 执行后增量 re-index；「忽略」则丢弃。

### 错误处理

- 引用失效：显示「已删除」，不报错。
- 检索为空：正常回答并标注「未在笔记中找到相关内容」。
- 未配置 / 模型不可用：面板显示连接状态并引导设置。
- 流式中断：保留已生成部分并提供重试。
- 索引文件损坏：提示并自动重建。

### 测试策略

- 服务端纯逻辑单测：分块、余弦、引用过滤、增量 upsert/delete。
- 集成测试：Ollama/OpenAI 在沙箱不可用时跳过。
- 浏览器无头测试：增量推送、确认流程、面板渲染。

## 分期

- 第一期（MVP）：面板 + 知识库问答 + 总结 + 写作辅助 + 编辑确认流程 + 索引/重建 + 设置。
- 第二期：学习辅导 + 从笔记自动生成题目/闪卡。

## 实现状态

- 第一期与第二期均已实现：右侧助手面板、RAG 问答、总结本页、讲解本页、写入本页（确认）、从本页生成题目/闪卡（结构化 JSON + 确认写入题库）、增量/全量索引、`#settings` 设置页（主题 + AI 配置 + 索引 + 数据导入导出）。
- 结构化的题目/闪卡生成走 `/api/ai/query` 的 `direct` 模式（跳过 embedding/检索，只调 LLM），因此无需 Ollama 即可生成。
